## 실행 및 재시작

복사본의 `on-client`에서 `node --check student/extension.mjs`가 오류 없이 끝났다. 아래 명령으로 로컬 앱을 실행했다. `-NoNativeHost`는 이번 확인에서 계정·AI 연결을 시도하지 않기 위한 옵션이며, `5198`은 이번 점검에만 쓴 포트다.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\start-alekov.ps1 -NoNativeHost -Port 5198
```

시작 도구가 `http://127.0.0.1:5198/`을 안내했고, 브라우저의 첫 화면과 `student/extension.mjs` 요청은 모두 HTTP 200이었다. 앱을 종료하고 같은 명령으로 다시 켠 뒤 브라우저를 새로고침했다. 2026-11-03 09:30:59에 「연결 없음」과 세 탭이 다시 표시됐다. 이는 앱 시작과 화면 표시의 재현이며 운영 연결의 성공은 아니다.

**후속 확인:** 공식 Node.js `v24.19.0` Windows x64 ZIP의 SHA-256을 공식 릴리스 값 `57f71ab3652e797d84acddc79c81cc9ff1c6ddb2a1974cdb83f00fee9bff4c73`과 대조했다. 별도 `aleph-launcher`에서 Node 경로를 그 PowerShell 창에만 추가해 기존 바탕화면 `on-client`를 `-NoNativeHost -Port 5198`로 다시 실행했다. 시작 안내와 HTTP 200, 학생 코드 문법 검사 통과를 확인했다. 이는 Node 준비 문제를 해결한 로컬 실행 확인이며 연결 결과는 이전 표와 같다.

**사용자 창의 기본 실행 확인(10:44 KST):** 사용자가 Node.js 버전 확인 후 기존 바탕화면 `on-client`에서 `-NoNativeHost` 없이 시작 도구를 실행했고 `http://127.0.0.1:5189/`이 열렸다. 이 주소는 HTTP 200이며 화면에는 「연결 없음」이 표시됐다. 도움정보의 `engine.mode`는 `disconnected`, `engine.code`는 `ENGINE_NOT_CONNECTED`, `ai.configured`와 `ai.authorized`는 모두 `false`였다. 「현재 로그인 확인」은 「서버에 확인된 계정 연결이 없습니다」를 표시했다. 사용자의 앱에서 「내 PC 확인」은 CPU·메모리·디스크·네트워크·Windows 기록을 읽었고, Windows 방화벽은 Domain·Private·Public 모두 켜짐으로 읽혔다. 이는 앞선 Codex 점검 계정에서 방화벽 읽기 권한이 없었던 결과와 구분한다. 패키지 조회는 여전히 `PROJECT_NOT_CONFIGURED`였다. 이번 실행으로 **로컬 앱 시작과 PC 실측**이 확인됐으며 SDP·AI·OSV 실제 연결은 확인되지 않았다.

**계정 연결 후속 확인:** 같은 날 사용자 화면에서 「계정 연결 확인 완료, AI 앱 승인은 별도입니다」를 확인했다. 이 상태는 앱의 계정 연결 성공을 뜻하지만, AI 앱 승인은 아직 시작 전이고 상단의 「연결 없음」도 그대로다. SDP 엔진 연결, AI 모델 응답, 실제 사건 설명 및 단계 통과와 구분한다. 확인 번호·자격 정보는 기록하지 않았다.

**AI 승인·모델 응답 후속 확인(11:01 KST):** 사용자 화면에 「연결이 완료됐습니다」와 「앱 권한 확인 후 모델 응답 점검(verified)」, 응답 모델 수 **1**이 표시됐다. 화면의 점검 시각은 `2026-11-03T02:01:49.957Z`이다. 이로써 이 노트북의 0.2.21 앱에서 **계정 연결, AI 앱 승인, 현재 권한의 모델 응답**을 확인했다. 이 화면은 실제 XDR 사건 설명, 조치, SDP 엔진 연결, 공식 17단계 판정까지 확인한 결과가 아니다. `/api/diagnostics`의 `ai.configured`와 `ai.authorized`는 제공 코드상 native 호스트 AI 점검을 반영하지 않으므로 이 결과의 반증으로 사용하지 않는다.

## 2026-11-05 · 2일차：提供 PC 조회 활용 및 이전 실측 비교
제공 수집 경로는 src/pc-status.mjs → src/server.mjs /api/pc/status → public/pc-status-view.mjs이다. CPU는 약 200ms 구간, 메모리는 물리 메모리, 디스크는 앱 파일시스템의 여유 공간이다. 수집 기능을 중복 구현하거나 관리자 권한을 요청하지 않았다.
추가한 표시 기능은 카드별 KST 조회 시각, GiB 단위, 직전 조회 대비 CPU·메모리 %p와 디스크 여유 GiB 비교, 최근 30회 추이·기록이다. 미조회·결측·실패는 0이나 예시로 대체하지 않는다. 기록은 새로고침하면 초기화된다. 공통 measuredAt은 전체 수집 완료 시각으로 개별 센서의 정확히 동일한 측정 순간을 보장하지 않는다.
검증용 모의 입력은 실제 화면의 실측과 분리했다. 최초/두 번째 비교, 권한 부족, 잘못된 값, 통신 실패, 오래된 응답, 30회 제한, 실제 0값 구분 시험을 통과했다.

$env:Path = "$env:USERPROFILE\Downloads\node-v24.19.0-win-x64\node-v24.19.0-win-x64;$env:Path"

2일차 실제 화면 검증(2026-11-05 17:25~17:26 KST): 최초 조회에 이전 실측 없음, 두 번째 조회에 CPU 18.2%→20.1%, +1.9 %p 표시를 확인했다. 메모리와 디스크에도 KST 시각·GiB·이전 시각 대비 비교가 표시되고 추이·기록은 두 개로 증가했다. 아주 작은 변화는 0.0으로 단정하지 않고 증가/감소 0.1 단위 미만으로 표시하도록 보완했다. 실패·결측 검증은 모의 입력 시험이며 실제 장애 발생 기록이 아니다. 작업 관리자와의 수동 동시 비교는 아직 실시하지 않았다.

## 2026-11-05 · 3일차 연결과 기록
제공 readPcStatus의 네트워크·방화벽·Windows 기록 조회를 재사용했다. 네트워크는 루프백을 제외한 인터페이스와 IPv4 구성 수이며 유선/무선·인터넷 성공으로 해석하지 않는다. Windows 기록은 System·Application 최근 24시간 경고·오류를 합산하고 최대 5,000건으로 집계한다. 집계 시작·조회 시각과 일부 집계 여부를 표시하며 침해나 공격 탐지 결과가 아님을 명시했다. 방화벽·보안 설정을 변경하지 않고 관리자 권한이나 공격 시험을 사용하지 않았다.
SDP는 PC 조회와 별도 버튼으로 /api/diagnostics의 엔진 상태만 읽는다. disconnected + ENGINE_NOT_CONNECTED일 때 SDP 미연결, demo일 때 예제 자료, 어댑터 설정만 있거나 상태·시각을 검증할 수 없으면 SDP 확인 불가로 표시한다. 진단 요청 실패와 시간 초과도 미연결로 단정하지 않는다. 이 진단은 서버 도달성을 직접 시험한 결과가 아니라 앱의 연결 설정 상태이다.
모의 검증: 권한 부족, 진짜 0건, SDP 미연결·예제·어댑터만 설정·알 수 없는 응답·오래된 응답·요청 실패 표시를 확인했다. 이 시험 입력은 실측 자료와 구별하며 앱에 예시값으로 주입하지 않았다.
재현 명령은 기존 on-client에서 다음과 같다.
```powershell
$env:Path = "$env:USERPROFILE\Downloads\node-v24.19.0-win-x64\node-v24.19.0-win-x64;$env:Path"
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\start-alekov.ps1 -NoNativeHost
```
http://127.0.0.1:5189/에서 새로고침 → 내 PC 확인 → 네트워크 구성 수·방화벽 세 프로필·System/Application 경고·오류 및 시각 확인 → 별도 SDP 상태 확인을 누른다. PC 실측 성공과 SDP 미연결이 동시에 표시될 수 있다. 실제 연결을 사용하려면 별도 계정·SDP 설정 확인이 필요하다. 포장·제출은 실행하지 않았다.

실제 브라우저 검증: 2026-11-05 17:36 KST. SDP 최초 표시는 확인 불가·아직 조회 안 함이며, 별도 상태 확인 후 미구성 진단에 따라 SDP 미연결로 표시됐다. 이어 PC 조회는 성공했고 네트워크 인터페이스 1개·IPv4 1개, 방화벽 세 프로필 켜짐, Windows 경고 149건·오류 148건 및 집계 시작/조회 시각이 표시됐다. PC 성공 후에도 별도 SDP 미연결 문구가 유지됐다. 모든 수치는 실제 조회이며 공격 시험·설정 변경을 하지 않았다. 실패·권한 부족 상태는 모의 입력 시험으로 확인했다.
